# C++ Server Study

C++ 소켓 프로그래밍과 멀티스레드 서버 구조를 직접 구현하며 학습하기 위한 프로젝트입니다.

단순 예제 코드를 따라 작성하는 것보다 **TCP 연결부터 다중 클라이언트 처리, 동기화, 사용자 관리까지 기능을 단계적으로 추가하면서 서버가 어떻게 동작하는지 이해하는 것**을 목표로 진행하고 있습니다.

## 현재 구현 상태

현재는 TCP 기반 1:N 채팅, 닉네임 관리, 방별 메시지 전달과 길이 헤더 기반 프레이밍을 구현했습니다.

```text
Client A ─┐
Client B ─┼── TCP ── Server : 7777
Client C ─┘
```

서버는 접속한 클라이언트마다 별도의 수신 스레드를 생성하고, 한 클라이언트가 보낸 메시지를 다른 클라이언트들에게 전달합니다.

### 구현된 기능

- TCP 서버 / 클라이언트 소켓 생성
- `bind`, `listen`, `accept`, `connect`를 이용한 연결 처리
- 1:1 채팅
- 1:N 실시간 채팅
- 접속 클라이언트 목록 관리
- 클라이언트별 수신 스레드 처리
- 메시지 브로드캐스트
- 닉네임 등록
- 닉네임 중복 검사
- 방별 메시지 전달
- 4바이트 길이 헤더 기반 메시지 프레이밍
- 사용자 접속 / 퇴장 알림
- 연결 종료 시 클라이언트 목록 제거
- `std::mutex`를 이용한 공유 데이터 동기화
- `std::lock_guard`를 이용한 RAII 방식 Lock 관리

## 학습한 내용

### TCP Socket

서버는 다음 순서로 클라이언트 연결을 처리합니다.

```text
socket()
   ↓
bind()
   ↓
listen()
   ↓
accept()
   ↓
recv() / send()
   ↓
close()
```

클라이언트는 다음 흐름으로 서버에 연결합니다.

```text
socket()
   ↓
connect()
   ↓
send() / recv()
   ↓
close()
```

### Multithreading

서버의 메인 스레드는 새로운 클라이언트의 접속을 계속 받으며, 접속한 클라이언트의 메시지 수신은 별도의 스레드에서 처리합니다.

```cpp
std::thread(
    receiveMessages,
    clientSocket,
    std::ref(clients),
    std::ref(clientsMutex)
).detach();
```

이를 통해 한 클라이언트의 입력을 기다리는 동안에도 다른 클라이언트의 메시지를 동시에 처리할 수 있도록 구성했습니다.

### 동기화

여러 클라이언트 스레드가 동시에 `clients` 목록을 조회하거나 수정할 수 있기 때문에 `std::mutex`를 사용했습니다.

```cpp
std::lock_guard<std::mutex> lock(clientsMutex);
```

직접 `lock()` / `unlock()`을 호출하는 대신 `std::lock_guard`를 사용하여 스코프를 벗어날 때 자동으로 Lock이 해제되도록 했습니다.

### Client 관리

클라이언트의 Socket과 닉네임을 함께 관리하기 위해 다음 구조체를 사용합니다.

```cpp
struct ClientInfo
{
    int socket;
    std::string nickname;
    std::string roomId;
};
```

연결이 종료된 클라이언트는 `std::remove_if`와 `vector::erase`를 이용해 목록에서 제거합니다.

## 빌드

프로젝트 루트에서 실행합니다.

### Server

```bash
clang++ -std=c++17 -pthread src/server.cpp -o server
```

### Client

```bash
clang++ -std=c++17 -pthread src/client.cpp -o client
```

## 실행

먼저 서버를 실행합니다.

```bash
./server
```

서버는 기본적으로 `7777` 포트에서 연결을 기다립니다.

```text
Server is listening on port 7777
```

다른 터미널에서 클라이언트를 실행합니다.

```bash
./client
```

여러 터미널에서 클라이언트를 실행하면 1:N 채팅을 확인할 수 있습니다.

```text
Client A ─┐
Client B ─┼─> Server ─> 다른 Client에게 메시지 전달
Client C ─┘
```

## 메시지 형식

모든 송수신 데이터는 다음 프레임을 사용합니다.

```text
[본문 길이: 4바이트 unsigned 정수, 네트워크 바이트 순서][본문: 지정한 바이트 수]
```

길이는 헤더를 제외한 본문의 바이트 수입니다. 클라이언트는 닉네임, 방 번호를 각각 한 프레임으로 보내고, 이후 채팅을 프레임 단위로 보냅니다. 서버의 채팅 전달, 접속·퇴장 알림, 닉네임 중복 응답도 같은 형식입니다.

- 닉네임과 방 번호: 각각 1~99바이트 문자열
- 채팅 본문: 1~4096바이트
- 서버 응답을 포함한 프레임 본문 상한: 4198바이트 (`[닉네임] ` 접두어 포함)

방 번호도 문자열로 전송하고 비교합니다. 예를 들어 `1`과 `01`은 다른 방입니다. UTF-8 입력의 길이는 글자 수가 아닌 바이트 수로 계산합니다.

수신 시 헤더와 본문을 각각 필요한 길이만큼 반복해서 읽습니다. 여러 프레임이 함께 도착해도 다음 프레임의 데이터를 소비하지 않습니다. 길이가 0이거나 해당 단계의 상한을 넘으면 본문 메모리를 할당하지 않고 연결을 종료합니다. 프레임을 다 받기 전에 연결이 끊겨도 해당 연결을 정리합니다.

송신도 전체 바이트가 전송될 때까지 반복합니다. 서버는 기존 `clientsMutex`로 같은 소켓의 프레임 송신을 직렬화합니다. 구버전의 헤더 없는 통신 형식과는 호환되지 않으므로 서버와 클라이언트를 함께 다시 빌드해야 합니다.

